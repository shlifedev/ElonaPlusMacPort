# ElonaPlus 2.335 네이티브 호환성 조사

## 분석 범위와 재현

복원한 `work/decompiled/2.335/start.hsp`와 AX의 외부 함수 선언을 대조했다.
**이 보고서는 정적 소스 조사다. 실행 도달성, 호출 빈도, 실제 DLL 반환값,
원본과 이식판의 동등성을 검증한 결과가 아니다.**

| 입력 | 식별 정보 |
|---|---|
| 복원 소스 | CP932, 16,093,503 bytes, 618,613 lines |
| 소스 SHA-256 | `dce3e305f91e377fd669a045d9dce7cc197509d094852e56b67be312aa233725` |
| AX SHA-256 | `f1b1404060faa01dc1d3e46b9a58ba0c39cfd185afd33bdafc2287ee3e921d25` |

아래의 줄 번호는 이 소스 해시에만 해당한다. 원시 소스는 변경하지 않았다.

```sh
python3 tools/audit_compatibility.py
```

산출물:

- `work/reports/compatibility-2.335/audit.json`: 78개 함수의 선언 위치·별칭·인수·호출 후보 수·예시 위치, 위험 구문 목록.
- `work/reports/compatibility-2.335/audit.md`: 전체 라이브러리/함수 표.

도구는 문자열·주석을 가린 뒤 식별자와 명령/함수 호출 모양을 찾는다.
완전한 HSP 파서가 아니며 전처리, 분기·루프·콜백·간접 호출의 의미를 해석하지
않는다. 모든 외부 선언을 AX inventory와 순서·라이브러리·export 이름까지
대조한다. 게임 대사·URL·문자열 데이터는 예시 코드에서 가린다.

검증한 작은 합성 입력에서는 문자열/주석 속 가짜 호출을 제외하고 명령 위치를
세었으며 줄바꿈 수를 보존했다. 실제 입력을 재실행하면 동일 보고서를 확인한다.

## 외부 의존성 표

모든 78개 선언에서 최소 한 곳의 호출 후보가 발견되었다. 이것은 모든 기능이
오프라인 플레이 중 실행된다는 뜻이 아니다. 아래 수치는 **호출 후보 위치 수**다.

|---|---:|---:|---|
| exrand.dll | 2 | 7 | 추가 난수 생성기 |
| hspda.dll | 4 | 4 | 정렬·노트 데이터 처리 |
| hspext_ext.dll | 8 | 532 | 화면 효과·수학·Win32 입력 컨트롤 접근 |

| hmm.dll | 20 | 1,023 | 오디오·조이스틱 **및 게임 상태 비트 연산** |

## 우선순위별 구현 묶음과 검증 조건

### P0 — 게임 상태·난수·문자열 의미

**hmm.dll을 오디오 전용으로 분류하면 안 된다.** `HMMBITON` 946곳,
`HMMBITOFF` 3곳, `HMMBITCHECK` 9곳이 있어 합계 958곳은 상태 비트 처리다.
예를 들어 줄 291·296·299는 캐릭터 플래그, 6381·6386·6389는 아이템 플래그,
594047 이후는 캐릭터 정의 데이터의 비트를 설정한다.

- 32비트 비트 연산·출력 변수·`stat` 의미를 먼저 구현한다.
- Windows x86 참조 프로그램에서 비트 0/31, 음수 입력, 반복 설정·해제를 비교한다.
- `randomize/rnd`와 `exrand`를 별개로 검증한다. 줄 167–173에서 같은 seed를
  두 생성기에 전달한다. `randomize` 64회, `rnd` 12,732회 식별자 출현은
  실행 횟수를 뜻하지 않지만 두 경로가 모두 필요하다는 조사 근거다.

**CP932 바이트 의미가 게임 코드에 직접 들어 있다.** 리드바이트 범위
129–159 또는 224–252를 검사하는 분기가 네 곳이다.

| 위치 | 관찰한 동작 | 필요한 호환성 |
|---|---|---|
| 7957–7983 `talk_conv` | `strlen`, `peek`, 1/2바이트 전진, `strmid(..., 2)` | 대화 줄바꿈과 문장부호 처리 |
| 32217–32238 `cutname` | 폭 변환 뒤 바이트 단위 이름 자르기 | 길이 제한·반각/전각 이름 |
| 38654–38663 `gmes` | 리드바이트 검사 후 문자 단위 출력 | 메세지 출력·제어 코드 |
| 309068–309083 | 입력 컨트롤 위치를 CP932 바이트 수로 변환 | 캐럿 위치·입력 길이 제한 |

예를 들어 다음은 대사 데이터가 아닌 실제 처리 코드다.

```hsp
p@txtfunc = peek(msgtemp@txtfunc, p2@txtfunc)
if ( p@txtfunc >= 129 & p@txtfunc <= 159 | p@txtfunc >= 224 & p@txtfunc <= 252 ) {
    p@txtfunc = 2
}
```

UTF-8로 파일만 바꾸거나 UTF-8 런타임을 그대로 사용하면 이 바이트 판정은
동일한 의미를 갖지 않는다. VM 내부의 CP932 처리와 UI의 Unicode 처리를
분리해야 한다. 반각/전각 변환 함수는 줄 199·202에서
`LCMapStringA(GetUserDefaultLCID(), ...)`를 사용하므로 Windows 비교 때
실제 로캘도 기록한다. 가나·탁점·ASCII·문장부호·혼합 문자열·경계 길이를
참조 환경과 대조해야 한다.

### P0 — Win32 포인터 ABI를 전달하지 않는 어댑터

`varptr` 다섯 곳은 모두 `_fdialog`에 집중되어 있다.

| 위치 | 코드 형태 |
|---|---|
| 38617–38620 | `dim ofn@filedialog, 19`, 구조체 크기 `76`, `hwnd`, `hinstance` |
| 38621·38625·38629 | 문자열 주소를 int 배열 필드에 저장 |
| 38633·38636 | `GetOpenFileNameA varptr(ofn@filedialog)` / 저장창 호출 |

이는 32비트 `OPENFILENAMEA` 레이아웃에 의존하는 구체적인 지점이다.
호스트 포인터를 32비트 배열에 넣는 방식은 ARM64/x64에 그대로 사용할 수 없다.
우선 `_fdialog`의 입력·취소·출력 계약을 유지하는 플랫폼 파일 선택 어댑터로
해당 경계를 교체한다. 현재 조사 범위에서는 범용 포인터 에뮬레이션을 먼저
만들 이유가 발견되지 않았다. 교체 전에는 원본의 취소·오류·파일 필터·경로
결과를 확인한다.

또한 외부 선언에 `bmscr`, `pval`, `pexinfo`, `prefstr`가 있다. DLL 함수를
같은 인수 개수의 C 함수로 연결하는 것만으로는 호환되지 않는다. VM 값과
화면 버퍼를 타입이 있는 내부 어댑터로 전달하고, 원본 DLL ABI를 새 호스트에
복사하지 않는다.

### P1 — 저장·메모리 레이아웃

- `memcpy` 20곳, `memset` 8곳, `wpeek` 7곳, `wpoke` 4곳이 있다.
- 줄 199789–199790에서 캐릭터 배열을 `600 * 4 * 2`, `500 * 4` 바이트로
  복사한다. 줄 306815는 사용자 NPC 데이터를 `70 * 4` 바이트로 쓴다.
- 줄 307285–307312 부근에서 `gdata`, `cdata`, `sdata`, `spell`을
  `zRead/zWrite`로 직접 입출력한다. 호스트 포인터 너비에 맞춰 배열 원소
  크기를 늘리면 저장 데이터가 달라진다.
- `zOpen/zRead/zWrite/zClose` 호출 후보는 각각 30/50/48/22곳이다.
- 줄 306639–306679의 `zipadd2/unzip2`는 40바이트 이름과 10바이트 길이
  필드를 직접 이어 붙이고 읽는다. 함수 이름의 `zip`만으로 표준 ZIP
  라이브러리로 바꿔서는 안 된다.

원본에서 만든 작은 데이터·빈 파일·경계 크기·손상된 스트림을 참조 입력으로
사용한다. 압축 스트림과 그 위의 게임 컨테이너 형식을 나누어 비교하고,
직렬화된 정수·배열 배치가 양 플랫폼에서 동일해야 한다.

### P1 — 그래픽·입력·오디오

- `gfini` 262곳, `gfdec2` 247곳이 UI 그리기 주변에 있다. 원본 작은 버퍼에서
  복사·감산·클리핑 결과를 얻어 공통 렌더러와 비교한다.
- `_grotate@16` 6곳과 water 플러그인 5개 함수는 별도 효과 어댑터로 다룬다.
- 줄 309007–309068은 `mesbox`, `aplsel/aplobj/apledit`으로 Win32 입력
  컨트롤에 접근한다. 줄 38574–38582는 IME 핸들을 얻고 해제한다.
  게임 내 문자열 입력 경계로 묶어 키 입력·Unicode 조합·CP932 변환을 구현한다.
- `mesbox` 5곳, `objprm` 29곳, `button` 8곳, `input` 5곳이 있다.
  SDL 창이 뜨는 것만으로 입력 UI가 완성되지는 않는다.
- `ginfo`는 20회 출현하며 리터럴 인덱스 0/1/2/4/5/12/13/16/17/18/22/23을
  사용한다. 각 값의 의미와 실제 사용처를 런타임에 매핑해야 한다.
- 줄 24004–24021은 음악·효과음·조이스틱 초기화 반환값에 따라 설정을 바꾼다.
  오디오 초기화에 무조건 성공/실패 값을 반환하면 원본과 다른 경로로 진행한다.
- `CreateMutexA` 결과는 줄 309822–309825에서 `stat` 및 마지막 오류로
  검사한다. 단일 실행 정책을 구현하더라도 실제 호스트 핸들을 게임 int에
  그대로 저장하지 않는다.

### P2 — 오프라인 범위에서 분리할 통신·ActiveX

`axobj` 두 곳(205172, 205259)은 `Shell.Explorer.2`를 만들고 `comevent`와
COM `Navigate`를 사용한다. 주변 소스는 사용자 콘텐츠 업로드 및 투표
브라우저 문맥이다. 진입 후보는 205019·305060·365345에 있다.

초기 오프라인 버전에서는 해당 기능 진입을 명시적으로 차단하고 비활성 상태를
표시한다. `axobj` 또는 네트워크 함수에 더미 성공을 반환해서 이벤트 대기
루프로 들어가게 만들지 않는다. `delcom` 정리 경로도 생성 여부와 함께 다룬다.
이 판단은 관찰한 문맥에 따른 구현 분리 제안이며 전체 제어 흐름 분석 결과는 아니다.

`exec` 네 곳은 외부 실행/문서 열기 경로이므로 각각 목적을 확인해 OS의 파일
열기로 대체하거나 비활성화한다. 네트워크 기능 전체와 무조건 묶지 않는다.

## 발견하지 않은 구문과 남은 검증

이 소스의 lexical scan에서는 `dupptr`, `objinfo`, `newmod/delmod/setmod`,
`callfunc`, `run`, `sendmsg` 후보가 없었다. `#module`, `#modinit`,
`#modterm` 지시어도 없고 AX 함수 인수 목록에는 module-variable 타입
(-7/-11/-20)이 없었다. 이 결과는 이 버전·이 복원물에 한정되며 다른 버전의
지원 여부나 해석되지 않은 코드의 부재를 증명하지 않는다. `@`로 한정된
변수 이름이 있다는 사실만으로 module-variable 객체 사용으로 분류하지 않는다.

다음 구현 순서는 상태 비트·난수 → CP932 연산 → 저장 레이아웃 → 화면 버퍼와
입력 UI → 오디오·효과 순서가 적합하다. 파일 선택·IME·메뉴는 플랫폼 어댑터로
분리하고 통신/ActiveX 진입을 오프라인 정책으로 차단한다.

정적 조사에서 네이티브 이식이 불가능하다는 근거는 발견하지 않았다. 다만
CP932와 32비트 포인터·플러그인 구조체 의존성은 **현재 OpenHSP를 빌드하는
것만으로 해소되지 않는, 실제 구현과 원본 비교가 필요한 호환성 관문**이다.
이 단계에서는 이 관문을 통과했다고 주장할 수 없다.
