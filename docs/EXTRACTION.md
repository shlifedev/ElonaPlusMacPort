# ElonaPlus 2.335 정적 추출

## 상태

`tools/prepare_game.py`는 원본 실행 파일을 실행하지 않고 PE32 말미의 DPMX
패키지를 검증·추출한다. 원본 폴더를 수정하지 않으며 추출 디렉터리가 이미
있으면 모든 산출물이 동일한 경우에만 재사용한다. 다른 파일이 있거나 내용이
변경되었으면 덮어쓰지 않고 실패한다.

이 단계는 **게임 실행, 전체 명령어 해석, 역컴파일 결과의 정확성, 재빌드 및
플레이 호환성을 검증하지 않는다.** 라이브러리와 함수 목록은 저장된 선언이며
실제로 실행된 호출이나 도달 가능한 코드를 뜻하지 않는다.

## 재현

저장소 루트에서 Python 3.10 이상으로 실행한다. 외부 Python 패키지는 필요 없다.

```sh
python3 tools/prepare_game.py --game-dir elonaplus2.335 --output work/extracted/2.335
python3 -m unittest discover -s tests -p 'test_extract.py' -v
```

처음 실행하면 `Created`, 같은 입력·출력으로 다시 실행하면 `Verified identical`을
출력한다. 검증 실패 시 종료 코드는 1이다. CLI는 아래 원본 실행 파일 해시만
허용한다. 새 버전은 별도 기준과 검증을 추가해야 하며 강제 무시 옵션은 없다.

산출물은 다음과 같다.

| 파일 | 내용 |
|---|---|
| `scene1.hsp`, `scene2.hsp` | 패키지 내 원시 리소스 바이트 |
| `start.ax` | 복호화한 원본 HSP 바이트코드 |
| `inventory.json` | 구형 헤더, 영역, 라이브러리·함수·인수 선언 목록 |
| `manifest.json` | 원본/멤버/추출물 해시, 파일 위치, 분석 범위 |

생성 시각이나 머신별 절대 경로를 보고서에 넣지 않아 같은 입력의 보고서가
동일하게 생성된다. 추출 디렉터리 전체는 `.gitignore`의 `work/` 규칙으로 제외된다.

## 확인된 원본

| 항목 | 값 |
|---|---|
| 실행 파일 | `elonaplus2.335/elonaplus.exe` |
| 실행 파일 크기 | 15,181,992 bytes |
| 실행 파일 SHA-256 | `7d372ac439788de5288cacf200d46d4352d036aa74ae5715f654aaeab56a1e4e` |
| DPMX 시작 | 파일 오프셋 159,744 |
| DPMX 멤버 수 | 3 |
| `start.ax` 저장 위치 | 파일 오프셋 335,381 |
| 복호화한 AX 크기 | 14,846,611 bytes |
| 복호화한 AX SHA-256 | `f1b1404060faa01dc1d3e46b9a58ba0c39cfd185afd33bdafc2287ee3e921d25` |
| AX 헤더 | HSP3 object format `0x301`, 96 bytes |
| 변수 수 | 2,860 |
| 레이블 수 | 9,949 |
| 라이브러리 선언 | 14 |
| 전체 함수/사용자 함수 선언 | 722 |
| 외부 함수 선언 | 78 |
| 인수 선언 레코드 | 1,234 |

`0x301`은 오브젝트 형식 값이다. 정확한 HSP 컴파일러 제품 버전을 식별한
것으로 해석하지 않는다. 라이브러리 선언의 사용하지 않는 필드에는 비정상으로
보이는 잔여 값도 있어 원시 값으로 보존한다. 이를 메모리 주소나 유효한 CLSID로
해석하지 않는다.

헤더의 `runtime` 값은 DS 상대 주소가 아닌 AX 파일의 절대 오프셋이며,
inventory에서는 `runtime_file_offset`으로 표시한다. 이 원본의 값은 0이다.
런타임 옵션 영역 때문에 코드 시작이 96 bytes보다 뒤에 있는 오브젝트는
이 추출기의 좁은 지원 범위에 포함하지 않는다.

## 검사 범위

- PE 시그니처·i386/PE32 형식·섹션 경계·섹션 겹침을 검사한다.
- PE 섹션 끝의 DPMX 디렉터리, 멤버 수, 저장 범위와 겹침을 검사한다.
- 경로 탐색, 절대 경로, Windows 예약 이름, 대소문자만 다른 중복 이름,
  보고서 파일명과 충돌하는 멤버를 거부한다.
- HSP의 바이트 차분/XOR/덧셈 변환을 해제한다. `HSP3` 네 바이트만으로는
  변환이 유일하지 않을 수 있어 헤더와 전체 선언 구조도 검증한다.
- 헤더의 전체 크기, 영역 경계·겹침, 레코드 크기, 레이블 대상,
  함수의 라이브러리·인수·이름 참조를 검사한다.
- 출력이 원본 폴더와 같거나 그 안 또는 상위에 있으면 거부한다.
- 출력 디렉터리 또는 기존 산출물의 심볼릭 링크를 허용하지 않는다.
- 새 출력은 별도 임시 디렉터리에서 완성한 뒤 디렉터리 단위로 게시한다.

지원 범위는 관찰한 2.335의 레이아웃이다. 임의 PE 패키지, HSP2,
확장 플러그인 테이블, 다른 헤더 버전을 일반 지원한다고 주장하지 않는다.
파일 읽기는 64 MiB로 제한한다. 추출 도구를 신뢰하지 않는 프로세스와 같은
출력 경로에서 동시에 실행하는 보안 경계로 사용하지 않는다.

외부 선언을 네이티브 호환 계층의 조사 입력으로 사용할 수 있다.
